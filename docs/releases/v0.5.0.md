# Herdr Mise v0.5.0

## Purpose

This release gives the read-only Herdr visualizer a minimal browser chrome that leaves the kitchen in view, and updates its dependencies.

The browser chrome is now one attention-ordered top bar and one bottom-right tools pill. The top bar puts the count of agents waiting at the pass first, then the longest wait, **Next blocked**, and the cooking and plated counts. The tools pill holds the workspace filter, **Freezer**, **Recap**, and **Settings**. Surfaces are frosted where the browser supports it, with opaque fallbacks, and use the existing presentation tokens. Panels open beside their control, on whichever side has more room, and stay within the viewport, so a station's details open with its pane locator in view. The playground introduction now fits beside the kitchen without scrolling.

The dependency updates are pixi.js 8.22.0 and vite 8.3.2, which affect the embedded browser bundle, and development tooling: vitest 5.0.3, @types/node 26.6.4, oxlint 1.86.0, oxfmt 0.71.0, and jsonschema 0.58.4 for protocol schema tests. The Herdr protocol, its schema, and the server's runtime behavior are unchanged.

## Install

Download the archive for your supported target and its matching `.sha256` sidecar from the [v0.5.0 GitHub release](https://github.com/funsaized/herdr-mise/releases/tag/v0.5.0). Verify the checksum before extraction or launch (replace `<target>` with a supported target):

```sh
shasum -a 256 -c herdr-mise-v0.5.0-<target>.tar.gz.sha256 \
  && tar -xzf herdr-mise-v0.5.0-<target>.tar.gz \
  && ./herdr-mise
```

On Linux, use `sha256sum -c` instead of `shasum -a 256 -c`. Run `./herdr-mise --tui` for the terminal interface.

On macOS or Linux x86_64 with Homebrew, run `brew install funsaized/tap/herdr-mise`, or `brew upgrade herdr-mise` for an existing install. Upgrade a Herdr-managed installation by rerunning `herdr plugin install funsaized/herdr-mise`. For standalone installations, rerun the pinned installer described in [operations](../operations.md#standalone-installer). Both modes verify the downloaded release before atomically switching `current`, retain the previous version for rollback, and support idempotent reinstallation.

## Herdr compatibility

The checked-in compatibility matrix and sanitized fixtures are unchanged. They cover Herdr 0.7.5 (snapshot protocol 17), 0.8.0 (19), 0.8.2 (20), a 0.8.2 development commit (21), and 0.9.0 (22). Protocol 21 is pinned to a development commit, not a general 0.8.2 stable-release claim. Other releases on supported protocols are outside this tested matrix. Missing or incompatible local sources show a labeled demo feed rather than live data.

## Limitations

- Frosted surfaces depend on browser support for `backdrop-filter`; other browsers get opaque surfaces with the same layout. Reduced motion is honored.
- Notifications require an open page, live connectivity, and browser permission, and do not replay blocked work that existed before they were enabled. Recap is neither persisted nor backfilled.
- Herdr Mise remains read-only and local: it cannot control agents or expose a remote dashboard. The browser server binds only to loopback. Demo remains visibly labeled, and connecting/disconnected pages do not present retained records as current blocked work.
- Release targets remain macOS arm64 (`aarch64-apple-darwin`), macOS x86_64 (`x86_64-apple-darwin`), and Linux x86_64 glibc (`x86_64-unknown-linux-gnu`, Ubuntu 24.04 / glibc 2.39 baseline). Older glibc, musl, Windows, and Linux ARM are not claimed supported.
- The TUI requires a UTF-8-capable terminal with space for its compact or tiled layout. Screen-reader speech listening is not a release gate; automated accessibility and keyboard, focus, and announcement checks remain required.
