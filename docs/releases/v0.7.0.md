# Herdr Mise v0.7.0

## Purpose

This minor release makes repository verification and cleanup more reliable. The trusted PR gate now requires a ready, exact-head pull request with successful product jobs. Installer and public-artifact tests clean only their own temporary resources on success, failure and interruption, and public-artifact setup no longer leaves installation directories behind after validation failures. The shipped installer also cleans scratch setup failures and exits immediately on interruption while preserving the selected version. Contributor documentation now describes the current native verification and compatibility discovery workflows.

There are no intended browser/TUI behavior, protocol, dependency or architecture changes. Browser and terminal interfaces, installation modes, supported platforms and the read-only boundary remain unchanged.

## Install

Download the archive for your supported target and its matching `.sha256` sidecar from the [v0.7.0 GitHub release](https://github.com/funsaized/herdr-mise/releases/tag/v0.7.0). Verify the checksum before extraction or launch (replace `<target>` with a supported target):

```sh
shasum -a 256 -c herdr-mise-v0.7.0-<target>.tar.gz.sha256 \
  && tar -xzf herdr-mise-v0.7.0-<target>.tar.gz \
  && ./herdr-mise
```

On Linux, use `sha256sum -c` instead of `shasum -a 256 -c`. Run `./herdr-mise --tui` for the terminal interface. Upgrade a Herdr-managed installation by rerunning `herdr plugin install funsaized/herdr-mise`, or rerun the pinned [standalone installer](../operations.md#standalone-installer). Homebrew users can run `brew update && brew upgrade herdr-mise`.

## Herdr compatibility

The checked-in compatibility matrix and sanitized fixtures are unchanged. They cover Herdr 0.7.5 (snapshot protocol 17), 0.8.0 (19), 0.8.2 (20), a 0.8.2 development commit (21), and 0.9.0 (22). Protocol 21 is pinned to a development commit, not a general 0.8.2 stable-release claim. Other releases on supported protocols are outside this tested matrix. Missing or incompatible local sources show a labeled demo feed rather than live data.

## Limitations

- Herdr Mise remains read-only and local: it cannot control agents or expose a remote dashboard. The browser server binds only to loopback. Demo remains visibly labeled, and connecting/disconnected pages do not present retained records as current blocked work.
- Release targets remain macOS arm64 (`aarch64-apple-darwin`), macOS x86_64 (`x86_64-apple-darwin`), and Linux x86_64 glibc (`x86_64-unknown-linux-gnu`, Ubuntu 24.04 / glibc 2.39 baseline). Older glibc, musl, Windows, and Linux ARM are not claimed supported.
- Notifications require an open page, live connectivity, and browser permission, and do not replay blocked work that existed before they were enabled. Recap is neither persisted nor backfilled. Reduced motion is honored; browsers without `backdrop-filter` use opaque surfaces.
- The TUI requires a UTF-8-capable terminal with space for its compact or tiled layout. Screen-reader speech listening is not a release gate; automated accessibility and keyboard, focus, and announcement checks remain required.
